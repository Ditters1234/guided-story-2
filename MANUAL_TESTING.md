# Guided Story 2 — manual testing

## Start

Double-click **Guided Story 2.exe** in this folder. This Windows build includes the interface; Node, Rust and the development server are not needed to run it. Windows and the Microsoft Edge WebView2 runtime are required. This is a development testing build, without an installer or automatic updates. `BUILD.json` identifies the source revision and executable checksum.

The app reopens the last story you successfully opened or created. On first launch, choose **New story** or **Open story**. New stories start empty unless you select the optional Brasswater example. Give a new story a name and choose a parent folder; each story has its own portable folder. **Project → New project / Open project** remain available while working. Keep your working stories outside this testing-build folder so you can replace the executable independently.

This node revision uses **story format 2** and requires a fresh story folder. An older remembered prototype story is preserved and rejected with a New/Open choice. After creating a new story, close and relaunch to check that it returns. The folder choice is stored with device settings, outside story projects. If the folder was moved/deleted, is locked, or cannot be read, an error and the New/Open choices should appear without loading example data or overwriting the saved choice. Canceling the folder picker should leave those choices available. An explicit `--project` launch overrides the remembered folder.

The settings gear contains Appearance, Custom themes, LLM, Prompts and Images. Existing device settings are preserved. Appearance and API settings stay separate from story folders. The offline demo provider lets you test proposal review without an LLM; its output is deterministic sample data, not a quality demonstration.

In **Settings → Prompts**, choose an AI tool and edit its base system instructions. Save, close/reopen and check the text survived. Try editing two tools before saving, then restoring just one with **Restore default** and saving again; the other edit should remain. Empty/invalid saves should retain your input and show an error. API settings and saved credentials should survive prompt edits. **Prompts** shortcuts in Story and AI world tools should open the relevant tool's instructions after saving the current draft. Editing prompts must not generate text or accept anything. The offline demo does not follow style instructions; test instruction quality separately with your model.

For story-specific guidance, open **AI context** from the World toolbar or Story composer. Include an existing node, or choose **New context note** and write its instructions/rules. Choose Instructions or Reference facts, the AI tools, order and content fields. Preview each tool: the included cards and assembled instructions should reflect those choices. A narration note can target passage writing/wording while world rules target other tools. Disable/re-enable an inclusion and reopen the story to check its configuration survives. Removing an inclusion must keep its node; deleting a bound node must remove its inclusion. Empty required content or an oversized request should report the source rather than silently omit it. The offline demo verifies the review flow, not compliance with style/rules. Historical wording and illustrations use their saved boundary; current-context edits affect new work.

Choose **Add node → Narration style** (also available in older stories) or **AI context → New narration style**. Check the defaults: Third person, Past tense, and Instructions for Passage writing/Wording edits. Edit person, tense and several lines of Narration instructions in the inspector, then open AI context and verify/edit those same fields and preview their inclusion. Other tools should receive no narration node unless selected. Disable/remove inclusion without deleting the node, re-enable it, and reopen the story. Generate / revise with AI can fill an empty instructions field; protect person/tense by unchecking them before generating and review before Apply. Multiple named profiles and custom nodes with the capability use the same controls.

## First pass: no model required

1. **World editing.** Add a place, character and item. Edit their names and descriptions. Attach the character to the place; put the item on the character or inside a container. Check the map and inspector agree. Try a custom node preset or relationship if useful.
2. **Save/reopen.** Close normally, reopen the executable and open the project folder. Check your edits, layout and clothing/possessions survived. Valid edits autosave; invalid form input is retained as a draft and should show an error rather than silently entering the world.
3. **AI proposal review.** Select Offline demo in LLM settings. In **AI world tools**, describe an addition or connected group. Generate, edit the proposal and Apply. Proposed records should not appear in the established world before Apply. Try **Generate / revise with AI** from a node's inspector.
4. **Story.** Switch to Story and choose **Generate passage** in the toolbar above the center editor. You can leave passage/chapter direction blank; check the editable location, viewpoint and present cast in the right pane. Alternatively provide direction or write prose manually. Generate creates a draft. **Check world changes with AI**, review the cards and approve each included change/note, then **Accept passage**. The contents list should update only after acceptance. Write another passage, optionally close the chapter, and inspect the next chapter's editable plan.
5. **History.** Use Contents and Previous/Next. Inspect Before/After world snapshots; they should be read-only. Return to Current world to edit. Try Edit wording, or Fork after this passage into a separate folder. Changing earlier events uses a fork; latest-event replacement has a separate reviewed action.
6. **Images.** In a saved node's Image section, choose Generate / choose image and import a small PNG/JPEG/WebP. Review it and choose Use as node image. For an accepted passage, use Illustrate passage. Import/generation alone should not publish an image. AI prompt tools use the LLM connection and Apply only prompt text; image generation remains separate.
7. **Backup/restore.** Export a backup from the Project menu into a different parent folder. Choose Restore backup and select the outer backup folder, then restore into a new folder and Open restored story. Verify prose, history, images and saved drafts; edit the restored copy and reopen it. The original and backup should remain unchanged. Select the outer backup folder, not its `project` child.

Try **Delete draft** beside a Story draft or saved AI world proposal. Cancel first to check that the draft stays, then confirm deletion. Delete both the current draft and an older one: other drafts and accepted/applied content should remain. Removing the last draft must not create a replacement; use Write next passage or reopen AI world tools to start fresh. Reopen the story and try backup/restore after deleting a draft to check it stays absent. Running work must be stopped before deletion.

After generating, the footer should say **Draft not accepted · check world changes first.** Choose **Check world changes with AI** beside the disabled Accept button. Each proposed change and note should appear as its own card. Try editing a description, capability field or connection target, removing an unwanted card, and approving the rest. Removing a proposed new place/item should preview dependent proposals before removal. **Validate reviewed changes** checks edits without another API call. Approval must survive closing/reopening, but editing an approved card must require its approval again; unrelated approvals should remain. Accept must stay disabled until every included card is approved and the set passes validation. Checking and approving alone must leave the established story unchanged. Editing checked prose should disable Accept again. For a deliberate unchanged world, choose **Use no world changes**; it clears the proposals and validates without an AI call, then still requires Accept.

If evidence validation fails, the affected cards should show **Source quote · needs correction**. Use **Choose quote from passage** or edit a continuous 8–600 character excerpt, reapprove that card and **Validate reviewed changes**. AI-added ellipses that skip or join text are invalid; literal ellipses already present in the prose are allowed. **Advanced JSON** retains raw editing and indexed native diagnostics for repair, but should be collapsed during normal review. The saved passage should remain intact throughout; generating new proposals is a separate explicit action.

If all cards are approved but validation is blocked, the header should explain that correction/validation is still required. A broken connection should be marked **Needs correction** with its reason on that card. Open **Edit** and use **Connection to update** to choose an existing connection or **Create new connection**. Correct the relationship/endpoints as needed: **Inside** is for place nesting; a character uses **Present at**. Reapprove edited cards and validate. Other approvals should survive, and the saved prose should remain intact. An update/removal pair using the same connection ID should mark both cards; remove the redundant proposal or explicitly create a separate connection.

## Node extensions

Before connecting a model, create a Character manually. Expand Profile, Goals, Voice and Appearance; leave unused values blank. Changes within an open section should keep it open. Under Manage extensions, add Detailed anatomy or another extension, review/apply it, then try changing the preset: existing capabilities/values remain until explicitly removed. Removing a capability used by a connection should fail safely. Clothing belongs in linked item nodes.

Use Define extension to add a choice, number and yes/no field. Review and apply; initially they should be unspecified. Enter zero and No, close/reopen, and confirm those remain distinct from unspecified. Define a custom node type from Character with Inventory item and Container added; all corresponding tools/sections should work together. Text in structured fields should be searchable. At enlarged text sizes, definition forms should scroll with Review/Apply visible.

Inspect image source facts for a character whose appearance and garment design use structured fields. Both the initial image prompt and optional AI prompt assistance should receive those values. No image generation or story event should occur merely from editing or opening sections.

## Your LLM

In **Settings → LLM**, select the compatible API provider, enter the base URL and optional key, then **Test connection**. Select a returned model and save. A single returned model is selected automatically. Testing fetches models without generating text. Approximately 30B/Qwen models are the initial target; adjust token budgets and API compatibility to your server. Unsupported sampling/thinking parameters produce an explicit error; the app does not silently retry another transport.

Start with one small node addition, then a short passage. Review the actual output and world effects before applying/accepting. Test a failed or cancelled request and confirm your existing prose/drafts remain. Model compatibility, generation quality and long-story continuity are part of this manual testing; they are not certified by the offline checks.

In a fresh empty story, AI world tools defaults to **Build a world from an idea**. Try a short premise with a location and two adults: check that the people have personal names and developed profiles, and that clothing appears as separate wearable items linked to each wearer. Select a proposed character to inspect **Worn items**, or use **Add worn item** and edit the new item's appearance/coverage/layer before Apply. Missing-outfit warnings are advisory so deliberately unclothed characters remain possible. Earlier accepted characters are preserved; generate a new proposal to test the updated creation behavior. Existing character rerolls protect Name unless you check it.

In a populated story, choose **New creation → Create a connected group**, select **Item only** under Group node types and request a kit of supplies. Select an existing owner under Context references to attach the new items. Review should contain only the selected node type, with no replacement setting/cast; existing nodes stay unchanged before and after Apply. Try a custom item preset and a mixed-type group. Switch between world/group/typed-node choices: direction/references should stay, while group filters and related-node controls reset appropriately. Close/reopen a saved candidate and check its scope survived. The offline demo supplies two sample group records; use your model separately to assess how closely generated content follows the request.

Select a character with worn clothes and a bag containing items, then start a new group: the current selection should start checked under Context references. Request supplies for that named character without ticking further references. Expand **Existing world context** after the direction saves; check the character, placements, clothing and container records are represented and any omissions are shown. Existing indexed people/containers should be available as proposed-link targets even without a manual reference checkbox. With your model, ask it to account for existing supplies; exact-name duplicates get advisory warnings and intentional copies remain possible. Close/reopen a candidate to inspect the same captured context. Edit a relevant world record and verify the candidate becomes stale rather than silently changing its source. Empty group output should explain that no new nodes were proposed and leave Apply disabled, with manual node creation still available. Older candidates need a fresh reroll for the new context check.

Create a named node with empty Story notes and Visible description (for example a Note called Narration style). Include it as Instructions for World creation/rerolls, then use its **Generate / revise with AI** action. Leave Direction empty, check Story notes and choose **Generate details**: it should produce a proposal without requiring placeholder text or disabling its inclusion. Repeat with a place, character or custom preset, including an empty custom text field. Uncheck every field to verify generation is disabled; leave Name and Visible description unchecked to verify they stay unchanged. Review, Apply and reopen to check persistence. Other empty required context sources must still report their names. The offline demo verifies the flow; use a model separately to assess the generated content.

Each worn garment should have just one **Worn by** link and appear in the character's **Worn & carried** list. To take it off while keeping it, use **Edit / move** and change that connection to **Stored in / carried by** with the same character. Change its target to a bag to store it there. **Detach** leaves the item unplaced. Older valid saves with separate inventory/wear links load as one relationship; their historical files stay unchanged. Pending AI proposals/checks from the earlier contract need a fresh review/reroll.

## Your image server

**Settings → Images** uses a direct, unauthenticated ComfyUI connection. Select the Guided Story Krea 2 profile matching your installation, or import an appropriate graph/binding profile for your model. Test connection checks workflow classes and installed choices without generating an image. Krea's loaders, custom nodes and filenames must match the installed workflow. Z-Image/MOSS require their own profiles; they are not checkpoint swaps in the Krea graph.

Try one small image. Generate image submits once; **Check result** retrieves the saved job explicitly. Review before accepting. A queued job retains its original endpoint and prompt ID across restart. An uncertain submission must be reconciled using its prompt ID; it never resends automatically.

## What to report

Record the build revision from `BUILD.json`, the action you took, what you expected, what happened, the exact error and whether restarting changed it. For provider issues, include the model/workflow name and relevant compatibility settings. Keep API keys and private story content out of public bug reports.

Current limits include bounded chapter memory, no semantic secrecy filtering for arbitrary prose, automatic acquisition/disclosure inference or general pinned-fact protection, no image reference conditioning, and folder backups below 4 GiB/25,000 files. Backup progress has no byte meter/cancel control; keep the app open during a transfer. Automatic interrupted-transfer discovery/cleanup, full version-history browsing, broad accessibility/scale testing and installer/release validation remain unfinished. Structural checks do not certify narrative meaning or image accuracy.

## Build from source

With the repository's Node/Rust/Windows build prerequisites installed, run `npm ci`, `npm run verify`, then `npm run manual:build`. The last command builds a standalone release executable and creates a new ignored `build/manual-test-*` folder containing only the executable, this guide, third-party notices and build metadata. It never packages stories, connection settings or development fixtures. `npm run desktop` remains available for development.

## Typed relationship pass

On a fresh fictional world, connect two characters with **Feels toward**. Fill attitude/reasons/tension and confirm the reverse relationship stays independent. Add an Organization with **Member of** and a role, an **Owes** link with terms/status, and a route with access/obstacles. Reopen the story and inspect the saved fields.

Use a connection’s **AI…** action with blank direction and empty checked fields. Only selected relationship notes/details should change; endpoints/type/ID stay protected. Generate details remains available with relationship fields selected and no node fields. Review and Apply explicitly. Test an unrelated manual change during generation separately from an endpoint/source edit; the latter must stale the proposal.

Create a custom relationship via **Add node → Define a relationship…**, adding Choice, Number, Yes/no and Node reference fields. Review/Apply the definition, use it on a connection, save zero/No, and reopen. Change a connection type and check that its review lists cleared old details. Try at 140% text in a small window; dialog actions stay visible while the form scrolls.

On a worn item, set **Wearing details** to “open coat, sleeves rolled.” Keep garment design on the item and one physical link. Confirm captured image facts include the wearing configuration. In passage review, edit/approve a relationship detail as a normal card; source quote errors and unknown fields must be editable on that card. Accept, inspect Before/After and fork after it; later manual edits must not rewrite those snapshots. These checks assess the flow; real-model output quality and ComfyUI execution require separate explicit tests.

## Event and source pass

Create an Event such as an old mill fire, fill What happened/When/Significance, and link participants and a place. Confirm it receives author provenance, without moving anyone or changing inventory. Revise blank fields using AI and apply; source metadata remains separately controlled.

In **Sources**, add an author note, then cite an accepted passage using a continuous excerpt and optional effect scope. Review/Apply, remove one citation and reopen. Read exact source, polish the passage and check the earlier-wording label. Edit the current node and check “Node edited since citation.” Historical source controls must be read-only. Removing an Event’s last passage citation explains that it remains author-established; replace a sole author source before removing that note.

Accept a passage with an individually approved Event card. Check Before/After, current source identity and effect number; no Event effects should replay. Fork after it, make the source project unavailable, and read the quoted evidence in the independent copy. A later Event/quote must be absent. Export/restore a backup including an earlier-wording citation. Try the Sources form at 140% text in a smaller window; footer controls should stay visible while the content scrolls.

## Visual style pass

Create **Visual style** through Add node or AI context, edit its palette/lighting and check that inclusion selects images and prompt assistance. Repeat with a custom node; including it should not follow its connections or add it to passage writing. Preview Image generation, then inspect **Image guidance & assembled prompt** and **Prepared workflow** in a node image. Optional prompt assistance should receive the same selected guidance once, and Apply should edit only the shot prompt.

Change the style while an unsent image is saved. Refresh guidance and confirm the manual prompt, negative prompt, seed and dimensions survive. Changing style should not label an accepted portrait's body/outfit as changed. A historical illustration defaults to its saved guidance; opting into Current world requires New shot. Fork after that passage: later guidance images must be excluded, while a full backup/restore retains them. Test at 140% text; footer actions remain visible. These checks do not establish real-model rendering accuracy.

## Claim and stance pass

Create **Knowledge / claim** for “the pump is cursed,” assess it as disproved and set access to narrator. Attach **Character stance** to Mara, who believes it, with an acquisition explanation. Add a revealed claim she does not know and a withheld claim. In Story select Mara’s viewpoint and review **Claim context**: belief, author assessment and reader disclosure must remain distinct. Author perspective can include narrator material but must still omit withheld claims. Required conflicting prose bindings should block generation with a repair message.

Cite a passage in Sources, edit a claim and review its edited-since-source indication. Reopen the story, inspect historical snapshots and fork before a later stance/disclosure edit. The fork must retain its earlier knowledge boundary; a full backup/restore must preserve both old history and current work. Check the scene pane at 140% text with the claim preview expanded; it should scroll without losing the central acceptance footer. Direction and ordinary notes are verbatim, so this does not test a semantic secrecy guarantee. See [knowledge behavior and limits](KNOWLEDGE.md).
