# Story-wide AI context

Use **AI context** in the World toolbar or Story composer, or **AI context → Manage / preview** in a node's inspector. Any world node, including a custom preset, can supply instructions or reference facts to selected AI tools. A plain **Note** preset and **New context note** action provide a convenient source for narration preferences, world rules, author guidance or background material. They use the same node/binding machinery as characters, items and places.

**Add node → Narration style** and **New narration style** in AI context create a standard node with a reusable Narration style capability: Narrative person (Third person by default), Narrative tense (Past tense) and multiline Narration instructions. The creation actions include it as Instructions for Passage writing and Wording edits, using Story notes and Capability fields. Edit its fields in the inspector or this manager, or use the ordinary Generate / revise with AI review flow. Person/tense are free text so unusual perspectives remain possible. Change its role, tools, order or enabled state through the same inclusion controls; remove inclusion to keep the node without applying it to prompts. Multiple named profiles are ordinary nodes, and the capability can be reused on custom nodes. AI world creation has an explicit **Create narration style and include it… on Apply** choice, which commits that binding with the reviewed nodes. Other AI-created nodes require separate inclusion configuration. Existing saved requests without that choice never acquire automatic bindings.

Each inclusion is a story-level binding to its source node, separate from physical map links:

- **Enabled:** temporarily stop inclusion while keeping its configuration.
- **Include as:** For text tools, Instructions are appended as labelled story instruction sections to the tool's editable base system message. Reference facts are supplied separately as `includedReferenceFacts` in the task input. Direct image preparation labels both roles in the submitted positive prompt.
- **Tools:** world creation/rerolls, passage writing, wording edits, effects extraction, chapter memory, image-prompt assistance and direct image generation. Direct image guidance also reaches optional prompt assistance; selecting both includes it once. Select all selects the currently supported tools; an empty selection sends nothing.
- **Order:** lower numbers appear first, with stable node-ID ordering for ties. Each role preserves that order in its own prompt section.
- **Content:** choose Story notes, Visible description and/or Capability fields. Capability values use the project's field labels, including custom fields. Node-reference values do not expand referenced nodes. No linked nodes or hidden container contents are followed through this binding.

The source node owns the text/fields. Editing them here or in the shared inspector changes the same record. Configuration and manual source edits autosave with the world. **Remove inclusion** leaves the node intact; removing a node through the normal validated operation also removes its inclusion. A disabled inclusion retains task, role, field and order choices. Up to 32 nodes can have bindings.

## Review what is included

Choose an AI tool in **Preview**. Cards show the selected source content in authored order. Expand **Assembled system instructions** to see the current base message plus instruction nodes, and **Reference facts supplied with the task** to inspect the separate reference sections. Scene direction, history, response schemas and other scoped task data are assembled by their existing tools; this is not a whole-request scene preview. Preview makes no inference request.

**Add node → Visual style** or **New visual style** explicitly creates a standard node with the reusable `detail.visual-style` capability. Medium, Rendering, Palette, Lighting, Composition and Image instructions are author-planning fields, separate from physical appearance. Creation selects Instructions for Image generation and Image-prompt assistance, using Story notes and Capability fields. Any custom node or other preset can use the same image inclusion; adding its capability alone does not silently enable a binding. These optional definitions install only on explicit creation in an older schema. Use **Preview → Image generation** for assembled direct guidance, or inspect the full captured prompt in the image editor. No LLM is needed for direct preparation.

A narration node can be Instructions for Passage writing and Wording edits, while magic rules can be Reference facts for world creation, passages and extraction. The standard preset uses the same node/capability/binding records; it does not add a separate narration collection. A bound node is not automatically a permitted edit target, a present participant or knowledge shared by every character. Apply/Accept and the native task schemas still validate proposed changes.

Claim nodes additionally obey the scene’s narration-access/perspective rules for prose and wording. A required binding to an excluded claim blocks the request rather than overriding access or silently dropping a required section. **Claim context** in Scene settings previews the applicable propositions/stances; this manager’s general preview has no scene perspective. Author-review and explicitly selected image context keep their own scopes. See [claims and filtering limits](KNOWLEDGE.md).

## Budgets and history

Included material is required context. It is added before optional story memory is budgeted and is never silently truncated/dropped. Requests that cannot fit report the included source names. Empty selected content blocks the matching request with a named repair message; an unfinished note can be filled in, excluded from that tool or disabled. There is also a 128 KB aggregate required-content bound.

To fill an unfinished source with AI, open its inspector's **Generate / revise with AI**, check the fields and choose **Generate details**. Existing descriptions and direction text are optional. For this request only, selected targets are editable source rather than fixed required instructions/reference sections; their context configuration is supplied to explain their intended use. All other required sources still apply. The proposal must be reviewed and applied before the source changes. Other tools continue to require nonempty included content.

Binding configuration lives in the world's optional `aiContext` field. Source nodes and bindings therefore travel with the story, immutable passage snapshots, backups and forks. Empty bindings are omitted so legacy stored-world receipts retain their original representation. Existing worlds load without a conversion; creating a Note in an older project explicitly adds that plain preset when needed. Older binaries cannot read worlds with the new nonempty field.

Older stories offer Narration style in Add node without rewriting their saved schemas. Choosing it explicitly installs its preset/capability in the current world; historical worlds and receipts keep their original bytes. The optional capability is validated when present, while existing required inventory/placement definitions remain protected. Its instructions use the generic `longText` field kind, with the same string limits, AI field protection and serialization as other text. Use the current app after saving this new field kind.

New passages use the current story bindings. Relevant included-source changes stale pending narrative checks, including changes made during generation; retained prose is not discarded. Image-only bindings do not stale a checked passage. Historical wording/event revisions use the saved passage boundary. Passage images and prompt assistance default to that same boundary; **Shot source & subjects → Image guidance → Current world (explicit)** opts into newer included guidance for a new shot. Node images use current guidance. Captures retain exact selected content and its immutable source world. A relevant change blocks an unsent image until **Refresh image guidance** or New shot; refresh preserves manual prompts, captured appearance and independent workflow controls. Accepted captures remain immutable. See [image guidance](MEDIA.md#image-guidance).

Prose extraction receives a task-scoped creation schema that omits unused author-only profiles. Native effect cards reject changes to planning-only fields and author-only presentation/planning profiles. Revise those through world tools; explicit instruction bindings still reach their selected text tasks.

Generated memory drafts capture their included context and require it to remain current before Apply. Accepted memory retains that provenance. A fork excludes a summary whose captured context differs from the fork boundary, avoiding copying later included knowledge into an earlier branch. Earlier accepted prose/world files are never rewritten when context nodes change.
