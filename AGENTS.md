# Project working guidance

## Authority and scope

Read README.md, DESIGN_REVIEW.md and REVIEW_AND_BUILD_PLAN.md before implementation. Confirmed user decisions take precedence over proposed details. EXISTING_WORK_REVIEW.md records the approved selective reuse direction and its constraints. Keep this as a fresh application; do not silently transplant the original Guided Story engine or a third-party writing application.

## First implementation milestone

Start with Gate 0: Windows Tauri/Svelte shell, a small map/inspector/image preview and validated JSON project create/open/save. Prove interruption recovery, revision publication, duplicate-request handling and project locking before broad feature work. Dependencies and code reuse need their own checks; the planning documents are not evidence of passing builds or runtime behavior.

## Core invariants

- The native backend owns canonical validation and project writes. Autosaved form drafts and AI proposals are distinct from accepted story facts.
- AI world proposals require Apply; prose requires Accept passage. Edited prose invalidates extracted effects and checks.
- Draft deletion is native-owned and version-checked. Protect running work, retained unsaved provider outcomes and accepted/applied receipts, including uncertain final status writes. Use atomic deletion markers to reject delayed writes/retries; hide markers from draft lists/counts and preserve them through backups/restart. Deleting a draft never changes canonical history or implicitly creates a replacement.
- Passage effects and continuity notes are individually edited, removed and approved in the draft. Native review keys bind each card to its complete contents, prose/plan, scoped source and proposed-node dependencies. Relevant edits invalidate approval; unrelated card edits preserve it. Require every included card's approval and native batch validation before publishing the passage atomically. Approval alone must never change the established world.
- AI node authoring derives fields, capabilities and output contracts from the project schema. Keep provider clients/job state separate from node data; custom presets must use the same creation/revision/protection pipeline.
- World building, connected-group creation and typed-root creation have distinct explicit intent. Group type limits constrain every new node in schema, candidate UI and native validation, including custom presets. Existing references authorize only scoped new links, never rewriting the established world. Preserve saved scope/legacy request serialization; new drafts default to World for empty stories and Group for populated ones.
- Groups automatically discover a bounded read-only existing-node index and relevant physical neighborhoods, with explicit/required context reserved first and coverage/omissions visible. New groups seed the current selection as a full-detail reference. Capture the exact index permissions and source boundary; permit new links only to supplied IDs, never existing-node/placement rewrites. Preserve captured context on reopen and reject forged/stale selections. Duplicate-name warnings are advisory; empty additions must not require invented duplicates or publish no-op commits.
- Existing-node AI authoring can develop empty checked fields from the node's name/type/context without prior descriptions or direction text. A selected target's AI context binding supplies intended-use metadata, not fixed instructions governing its own rewrite; all other required context remains enforced. Preserve checked-field protection and explicit Apply.
- Accepted passage versions and world snapshots are immutable. Current author edits must not change historical snapshots.
- Wording revision preserves events/snapshots and labels any evidence anchored to earlier wording. Latest-event replacement uses its recorded before-world and blocks intervening world edits rather than rolling them back. Superseded versions remain immutable; a fork omits alternate revision history except a required wording evidence anchor.
- Publish passage text, effects, chapter membership and before/after snapshots through the same manifest transaction. Manual world commits preserve its narrative reference. Narrative checks fingerprint exact prose/plan/effects and scoped source; ordinary navigation must never trigger generation.
- Use one Fork after this passage action. Copies must stand alone and exclude future story knowledge and pending operations.
- Clothing is inventory. Each item has one physical relationship: worn-by implies inventory membership; stored-in means carried or stored. Do not add a redundant possession link or separately editable wardrobe strings. Preserve immutable legacy files/checksums and verify completion receipts against their original stored representation.
- Use generic world nodes with reusable capabilities, project-local type/field definitions and typed links. Place/character/item/thread are presets, not hardcoded persistence collections. Container is an addable capability; custom nodes must roundtrip without engine changes. Keep built-in inventory/placement validation intact.
- Relationship details use project-local typed fields and shared validation/projections, not extra node collections. Existing-link AI revision protects ID/type/endpoints and unchecked properties; link-only and mixed requests share the node authoring pipeline. Group creation never gains existing-link edit permission. Typed link references participate in scope checks, alias allocation, card dependencies, removal cleanup, snapshots and backups. Wearing configuration is a visual/story property of the worn-by link; garment design stays on the item.
- Event is a shared preset/extension, not an event engine. Its author additions never replay effects; prose-derived Event citations attach only at reviewed atomic acceptance. Source annotations are typed native-owned node metadata with immutable checksummed text anchors and registered text/event identities. Preserve exact earlier wording, reject invented/future/superseded source versions, scope annotation context, and flag record changes since citation. Wording preserves event identity; replacement changes it. Forks retain only applicable/required anchors, preserve standalone identities and leave the source untouched. Backups validate anchor contents and passage registration. Keep source quotas actionable before acceptance and retain author provenance when removing the final Event citation.
- Windows file publication retries only access/sharing/lock errors with a fixed six-attempt/770 ms ceiling. Keep no-overwrite publication for immutable files and new project folders; persistent failure preserves the old head/incomplete stage. Never use filesystem retry handling to resend provider requests.
- Follow WORLD_NODE_DESIGN.md for the next node revision. Small behavioral capabilities enable native operations; presets bundle reusable descriptive extensions. Update the shared inspector, AI schemas/protection, task projections and media fingerprints together so new fields are actually used. Preset names must not gate capability-driven behavior.
- The user permits fresh stories for that revision. Older prototype format compatibility/import/migration is not required, superseding legacy-format compatibility requirements for the new format. Introduce an explicit format version; never overwrite/delete existing folders automatically. Preserve immutable histories, checksums, receipts, backups and forks within the supported format.
- Narration style is an optional standard preset/capability over shared world nodes and AI context. Its creation shortcuts select Instructions for Passage/Wording; inclusion remains configurable. Install optional definitions in older worlds only on explicit creation, preserving historical schemas/receipt hashes and required built-in validation. Multiline instructions use generic longText fields and the usual AI review/protection pipeline.
- Characters are accessed through the world map/shared inspector. Portrait generation does not redesign canonical facts.
- Visual style uses shared nodes and explicit image-preparation bindings. Keep presentation guidance separate from physical appearance, include it once in optional prompt assistance, and show the native assembled prompt. Capture its exact world/sections; historical shots default to their saved boundary, with an explicit current-world option. Refresh only unsent guidance without erasing prompts/controls. Style edits do not change physical applicability; forks exclude later guidance. Prose effects cannot rewrite author-only profiles or planning-only fields.
- Media retains exact source world/passage versions, appearance/outfit facts and submitted graph/endpoint/prompt ID. Images require explicit acceptance; publication/selection does not stale narrative checks by itself. Flush assets before atomic index publication. Uncertain submissions never resend automatically; forks exclude future/superseded source media and pending jobs.
- Optional LLM image prompts share text-job limits and use captured visible facts only. Apply updates the image draft, requires current source/settings and preserves independent controls. Keep receipt-based replay protection and compact provenance; never submit ComfyUI or change world/prose implicitly.
- Backups use an idle, serialized project snapshot and explicit file allowlist. Preserve full history and saved drafts; exclude global settings/credentials/locks. Validate checksums, schemas, references and images before publishing a new folder. Restore pins the reviewed manifest, retains story/operation identity and never overwrites work. Keep incomplete stages/replay protection; reset UI sessions when switching physical folders with the same story ID. Forks remain distinct.
- Scope model context by task, viewpoint and selected resources. Map expansion does not authorize sending the entire world.
- Explicit story-wide AI context bindings may select any node as Instructions or Reference facts for chosen text tasks. They are nonphysical metadata relationships with enabled/order/content-field controls, not new entity collections or implicit edit permission. Keep required sections intact, budget them before optional recall, and show the same assembled sections in preview. Preserve empty legacy world serialization, cleanup on node removal, captured historical boundaries and pending-result staleness. Do not expand connected nodes through these bindings.
- Chapter memory is reviewed derived history with exact passage-version sources. Exclude stale/future/unavailable summaries, reserve required context before optional recall, and report gaps/omissions. Summary generation is explicit, shares the single text-job limit, and never advances story events. Forks copy only fully retained current summaries and remap their sources.
- Prioritize approximately 30B/Qwen-class local models with compact scoped tasks and explicit server-compatible sampling/thinking controls. Preserve model-specific ComfyUI graphs; start from the pinned Guided Story Krea 2 templates and use separate graph profiles for Z-Image/MOSS. Do not silently swap loaders, conditioning, custom savers or sampler defaults between families. See MODEL_TARGETS.md.
- Shared AI base instructions live in the editable prompt catalogue. Every text task uses that effective saved base; only explicitly included story instruction nodes may extend it, with the assembled result visible in AI context preview. Keep schema/context assembly, budget checks and native output validation intact. Prompt saves have their own revision and preserve API forms/credentials; transport saves preserve current prompt edits. Empty default prompt settings must retain legacy serialized hashes.
- Preserve full retained prose on extraction/check failure. Never add unbounded automatic repairs, retries or provider switching.
- Reading navigation, layout and portrait selection must not accidentally advance or rewrite the story.
- Startup reopens the last successfully opened/created story, with an explicit --project path taking precedence. Store that folder choice in device-local config, never portable story data. No remembered/available story means a New/Open screen; never load Brasswater implicitly. Failure to remember a successful open is a warning, not a failed story operation.
- Keep the workspace compact and functional. Avoid slogans, repeated headings, development-status copy, placeholder tabs and redundant legends; prioritize room for the map and editing controls.
- Story mode uses chapter/passage/draft navigation on the left and scene planning/review on the right, with prose in the center. World mode uses the world tree and shared inspector.
- Use the shared appearance tokens for UI colors and scalable text. Appearance preferences belong in the app config directory, not story snapshots. Portable themes are validated JSON data, not executable CSS.

## Source, data and verification

Keep upstream reference checkouts out of tracked application files and packages. Record source revisions and preserve applicable third-party notices for actual reuse. Keep private stories, media, keys and local connection settings out of Git. Do not select a project-wide license implicitly through a starter template.

Use isolated fictional projects and deterministic provider adapters for tests. Live provider tests must be short, explicit and separate from normal user data; do not run lengthy generations merely to verify UI/storage changes. Report automated checks, desktop checks and real-model evidence separately. Run checks appropriate to each change, including interrupted-write tests when persistence changes. Do not claim a build or feature works without verifying it.
