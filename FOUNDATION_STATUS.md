# Desktop foundation checkpoint

Updated October 26, 2026. Desktop/storage foundation and a bounded world → passage → historical state → fork authoring loop. This is not the completed product or a release-ready application.

## Implemented

- Windows Tauri/Svelte shell with resizable Paneforge panes, Svelte Flow canvas, searchable tree and shared inspector.
- Compact settings dialog with Appearance, Custom themes and LLM categories; system/light/dark/sepia palettes, text scaling, reduced motion and a color-token editor with JSON import/export. Native app preferences use separate versioned, locked, atomic JSON files outside story projects. Windows DPAPI protects optional API keys. See [appearance settings](APPEARANCE.md) and [AI authoring](AI_AUTHORING.md).
- A shared world-node model. Places, characters, items and threads are presets; nodes carry capabilities and typed links. Project-local type, field and relation definitions are included in saved world snapshots.
- Custom node preset creation with optional inherited capabilities and custom text fields. Schema-driven inspectors support text, numeric, Boolean and node-reference properties; broader schema-authoring controls remain future work.
- Addable capabilities, including inventory, containers and wearability. Built-in semantic validation remains enforced regardless of a node's display type. Container is an extension of a node, not a separate persistence collection.
- Native-validated structural previews: create/edit/move/detach links, remove nodes while retaining contents, clear typed references, and remove capabilities after resolving dependent connections. Wear/possession transfers and custom physical links use the same atomic rules. See [world editing](WORLD_EDITING.md).
- Connection controls in the shared inspector, canvas connection creation, stable canonical canvas edge IDs, project-local relationship definition creation, and ancestor revelation when following connections. Thread grouping cannot create projection cycles; deep layouts/tree ordering use iterative traversal.
- New/open project commands, manual autosave, recoverable invalid form drafts, immutable world/manifest records and checksum-validated JSON reads. Readable app example data is fictional.
- OS project locks, stale-revision protection, idempotent request receipts, flushed same-filesystem head publication, previous-head recovery and independent layout versions. A closed/moved project has no dependency on its old absolute location.
- Tauri Specta-generated TypeScript command contracts, using a published compatible RC set. No hand-maintained duplicate canonical frontend schema.
- Shared AI creation/revision/reroll for built-in and custom nodes/capabilities, checked editable fields, explicit context references, idea-to-world groups and generic candidate editing. Native validation protects existing records and links; proposed character/outfit/container bundles apply atomically.
- Empty worlds default to idea-to-world groups. Creation asks for personal names/developed profiles and individual wearable items with a single Worn by physical placement, using a schema-derived garment example. Character presets enable related nodes; the candidate editor exposes worn items, quick garment creation, generic capability additions and nonblocking missing-outfit warnings. Existing accepted records remain unchanged. Wearing now supplies inventory membership without a second link; generic physical transfers replace it directly.
- Durable prompt/candidate records with independent versions, immutable source snapshots, scoped source fingerprints, retained malformed/truncated responses, cancel/interruption handling and receipt-based Apply reconciliation. Review survives restart; AI output does not autosave into canonical facts.
- Configurable non-streaming Chat Completions client with JSON/schema/prompt modes, explicit token-parameter compatibility, budgets/timeouts/response bounds and no automatic network retries/provider switching. Offline demo and local HTTP fixtures exercise the path without real model calls.
- Qwen-oriented local 30B sampling defaults for new connections, optional top K/min P and explicit thinking transports, plus a generic compatibility preset. Older saved settings keep their choices. Revision prompts send only relevant schema definitions and avoid repeating the response schema in schema mode. See [model targets](MODEL_TARGETS.md).
- Guided Story's two Krea 2 ComfyUI workflow data files, with source revision/hashes and explicit prompt/control/output bindings. Model, LoRA, encoder, sampler and custom save nodes are preserved. Other image families can supply separate JSON graph profiles. Settings → Images tests availability without inference; generation preflight blocks missing classes/installed choices and invalid bound controls without rewriting graphs.
- Reviewed node images and passage illustrations share a shot/prompt editor, manual import, durable ComfyUI submission and explicit result checks. Exact source world/text versions, worn item coverage/layers, prompts/graphs/endpoints/IDs and checksummed image files survive restart. Accepted media/portrait metadata uses atomic publication without changing world/text checks; map thumbnails, inspector images and reader illustrations share the assets. Historical mismatches are labeled/hidden as appropriate; forks copy only retained source media. See [media behavior and limits](MEDIA.md).
- Optional LLM image prompt suggestions use captured visible facts, author direction and workflow framing, with compact bounded requests through the shared text-job service. Review/edit/Apply changes only an unsent image draft; durable receipts preserve later work on replay. Suggestions, raw-response repair, cancellation/interruption, background status and compact accepted provenance use the same generic media flow.
- Shared first/later passage composer with manual prose, separate explicit narration/effects requests, durable candidates, source checks, evidence-scoped effects and atomic acceptance. Chapter closing and editable next-chapter plans, contents/Previous/Next, immutable before/after world inspection and inclusive independent passage forks use the same project aggregate. Story mode has chapter/passage/draft navigation on the left and scene planning/review on the right; World mode restores the tree/map/inspector. See [passage authoring](STORY_AUTHORING.md) for scope and limits.
- Accepted wording revision and latest-event replacement use separate saved candidates in the same composer. Wording keeps event snapshots/current world/later passages; replacement starts from the recorded before-world and blocks intervening world edits. Text diffs, earlier-version reading, versioned evidence anchors and receipt-based revision replay preserve provenance. Forks omit superseded alternate events and materialize only evidence sources required by retained events.
- Source-linked chapter memory with manual/explicit AI summary candidates, exact quotes and Apply. Bounded older-context retrieval combines current summaries and accepted notes, prioritizes scene references, reserves required context first and reports coverage/gaps/omissions. Revisions stale dependent summaries/checks; forks copy only fully retained current memory. Source reading and candidate repair use Story's center/right panes. See [memory behavior and limits](MEMORY.md).
- Project menu with validated folder backup/restore. Full history, earlier passage versions, memory, images, saved drafts/candidates and receipts are copied through bounded checksummed manifests and staged publication. Restore pins the reviewed backup and creates a fresh folder while retaining story identity; existing work is never overwritten. Source project operations are serialized and private global settings stay separate. See [backup behavior and limits](BACKUPS.md).
- Standalone Windows manual-testing build with embedded frontend assets, no development-server dependency and a console-free release executable. `npm run manual:build` creates a fresh ignored handoff folder containing only the app, [testing guide](MANUAL_TESTING.md), third-party notices and build revision/checksum metadata. `npm run verify` collects the existing checks. New projects default to an empty world; the fictional example remains optional.
